## 5. Fetch failures and caveats (recorded, not hidden)

- **Dead links:** runifyprivacy.carrd.co and runifytermsandconditions.carrd.co (linked from the iOS listing) returned 404 on 2026-11-16. runifyapp.com returned HTTP 402 Payment Required; the privacy policy was recovered from a Wayback Machine snapshot (2026-10-24), terms remain UNKNOWN.
- **Leap Fitness terms:** leap.app/terms, /legal, /terms-of-use, /terms-of-service and /eula returned HTTP 200 with a JSON 404 body; no public ToS/EULA text was found. Failure to find a term is not evidence that no EULA exists (the in-app EULA was not inspected).
- **Play help URLs now 404:** answer/9888184 and answer/9888117 were skipped; the health-permissions page actually used is answer/12991134.
- **DataGuidance** returned a blocked/empty page; no Iraqi data-protection statute could be verified from it.
- **Wayback API** rate-limited once (429); the archived page was fetched directly.
- **Tooling:** the environment's generic web-fetch API failed with a "multiple web providers registered" configuration error, so snapshots were taken with a normal HTTP GET through PowerShell and stripped to text. This does not change what was captured; it is recorded for reproducibility.

## 6. Handling rules for this directory

- KEEP for evidence and short quotation. Do not put these files in the app bundle, store listing, marketing or a public repository release.
- Quote at most five lines per clause, with attribution and URL; do not reproduce whole policies.
- Do not execute, extract from or link to any target binary from this directory; none is present.
- If this directory is ever published or shared outside the team, treat the third-party documents as third-party content and remove them first.
- Raw listing HTML in tmp/research/ is SEALED internal material, not a build input; delete it at the end of analysis after recording facts and hashes.
